# ТЗ: «Project Sus» — читалка с переводом слов

**Версия:** 1.1 · октябрь 2026 · MVP реализован (этапы M0–M4)
**Суть:** личный веб-сервис для чтения текстов на изучаемом языке. Читаешь, нажимаешь на незнакомое слово — рядом всплывает карточка с переводом на русский и кнопкой «послушать».

---

## 1. Цель

Сделать чтение польских текстов комфортным без прыжков в браузерные переводчики: слово и его перевод — в одном месте, в один клик, без потери места в тексте.

Главная метрика: **от клика по слову до перевода — меньше секунды** (при повторном слове — мгновенно, из кэша).

## 2. Пользователь и контекст

- Один пользователь — автор проекта. Аккаунтов, ролей и синхронизации нет.
- Запускается локально на своём компьютере.
- Сейчас изучается польский (`pl`), целевой язык перевода всегда русский (`ru`).
- Архитектура должна допускать другие изучаемые языки без переписывания (язык — свойство текста, а не константа).

## 3. Принципы

1. **Тексты — это файлы.** Обычные `.md` в папке `texts/`. Их видно, можно править в любом редакторе, бэкапить, хранить в git.
2. **Локально.** Наружу уходит только само слово, по которому кликнули. Тексты никуда не отправляются.
3. **Прозрачно.** Минимум зависимостей; каждая объяснима. Никакой магии «из коробки».
4. **Один экран — одна задача.** Главная — список текстов. Читалка — чтение.
5. **Русский интерфейс**, изучаемый язык — параметр.

## 4. Границы

| В MVP | Позже (v2) | Не планируется |
|---|---|---|
| Список текстов, добавление `.md`, удаление, переименование | Личный словарь сохранённых слов | Мобильное приложение |
| Читалка с рендером markdown | Интервальное повторение (SRS) | Аккаунты и облако |
| Клик по слову → перевод + озвучка | Другие языки интерфейса | Соцфункции, шаринг |
| Ручная правка перевода (запоминается) | IPA-транскрипция | Редактор текстов внутри приложения |
| Кэш переводов, IPA, личный словарь | Статистика и повторение | Целевые языки кроме русского |
| Поиск по названиям, тёмная и светлая тема | Личный словарь, статистика | |

**Осознанное ограничение:** текст нельзя редактировать в приложении — только в `.md`-файле. Приложение читает, а не пишет литературу.

## 5. Сценарии

- **US-1. Добавить текст файлом.** На главной жму «Добавить текст» → перетаскиваю `.md` → вижу превью названия → «Сохранить» → файл лёг в `texts/`, карточка появилась в списке.
- **US-2. Добавить текст вставкой.** То же окно, вкладка «Вставить текст»: ввожу название, вставляю содержимое, выбираю язык → «Сохранить».
- **US-3. Найти нужный текст.** На главной вижу карточки (название, язык, размер, дата). Ввожу часть названия в поиск — список фильтруется на лету.
- **US-4. Открыть и читать.** Клик по карточке → читалка: крупный текст, удобная ширина строки, кнопка «назад».
- **US-5. Узнать слово.** Клик по незнакомому слову → рядом карточка: слово, перевод, кнопка ▶. Клик вне карточки — закрылась. Нажал на слово — читаю дальше, текст не сдвинулся.
- **US-6. Поправить плохой перевод.** Перевод кривой → жму «✎» → вписываю свой → сохраняется навсегда, в следующий раз показывается мой вариант.
- **US-7. Удалить текст.** Меню на карточке → «Удалить» → подтверждение → файл удалён с диска.
- **US-8. Настроить чтение.** Крупнее шрифт, медленнее озвучка — настройки запоминаются между сессиями.

## 6. Функциональные требования

### FR-1. Главная страница

- Список карточек: название, язык (бейдж `PL`), количество слов, дата добавления, первые ~120 символов текста без разметки.
- Сортировка по дате добавления, новые сверху. Переключатель «А–Я».
- Мгновенный поиск по названию (без перезагрузки).
- Кнопка «Добавить текст» — заметная, в шапке.
- Пустое состояние: «Пока нет текстов. Добавь первый — это файл `.md`» + кнопка.
- Клик по карточке → переход в читалку.
- Ошибка загрузки списка → понятное сообщение и кнопка «Повторить».

**Приёмка:** добавил файл в папку `texts/` вручную, обновил страницу — карточка на месте.

### FR-2. Добавление текста

- Модальное окно с двумя вкладками: «Файл» и «Вставить текст».
- Файл: выбор через диалог или drag & drop, принимаются `.md`, `.markdown`, `.txt`, до 1 МБ.
- Вставка: поле названия (обязательное), большое поле текста, выбор языка (по умолчанию `pl`).
- Название по умолчанию — имя файла без расширения или заголовок `# ...`, если он есть.
- Валидация: пустой текст, неподдерживаемый формат, слишком большой файл — понятная ошибка по-русски.
- После сохранения: файл в `texts/`, переход в читалку нового текста (или хотя бы уведомление + карточка в списке).
- Дубликат названия — не ошибка, а предупреждение с автопереименованием (`-2`).

### FR-3. Читалка

- Рендер markdown: заголовки, абзацы, списки, цитаты, выделение жирным/курсивом, ссылки, код, разделители.
- Типографика для чтения: колонка шириной 60–70 символов, межстрочный интервал ~1.7, размер шрифта настраивается (16–28 px).
- Шапка: «← Назад», название текста, кнопка настроек чтения.
- Индикатор прогресса чтения — не нужен.
- Ссылки внутри текста остаются кликабельными и не превращаются в слова.
- Код и блоки `code` не разбиваются на слова.

### FR-4. Карточка слова

- Открывается по клику на слово, позиционируется рядом (над словом, при нехватке места — под ним), не выходит за границы окна.
- Содержимое:
  - слово в той форме, в которой оно в тексте;
  - транскрипция IPA, если слово есть в Викисловаре;
  - перевод на русский — крупно;
  - часть речи / пометка, если провайдер их дал (необязательно);
  - кнопка ▶ «Послушать» + переключатель скорости (в настройках);
  - кнопка «✎ Поправить перевод»;
  - маленькая подпись источника: «словарь», «кэш», «мой перевод».
- Состояния: загрузка (скелетон), ошибка («Не удалось перевести. Повторить»), пусто («Перевод не найден» + поле ввода своего варианта).
- Закрытие: `Esc`, клик вне карточки, повторный клик по слову.
- Если пользователь выделяет текст мышью (выделение не пустое) — карточка не открывается, чтобы не мешать.
- На узких экранах (< 640 px) карточка превращается в шторку снизу.
- Карточка не должна сдвигать текст: позиционируется абсолютно/фиксированно.

### FR-5. Произношение

- Озвучка через Web Speech API (`SpeechSynthesis`) голосом `pl-PL`.
- Скорость: 0.7 / 0.85 / 1.0, выбирается в настройках.
- Если польского голоса в системе нет — кнопка неактивна и подсказывает: «В системе нет польского голоса. Установи польский язык в настройках Windows».
- Повторный клик — переозвучивает с начала.
- Пока идёт озвучка — кнопка в состоянии «играет».

**Приёмка:** на Windows 11 с установленным польским голосом (Microsoft Paulina) слово произносится вслух с корректным польским произношением.

### FR-6. Разбиение на слова

- Использовать `Intl.Segmenter(lang, { granularity: 'word' })`, фолбэк — регулярка по `\p{L}\p{M}`.
- Пунктуация, пробелы, цифры остаются как есть и не кликаются.
- Диакритика (`ą ć ę ł ń ó ś ź ż`) — часть слова, не разделитель.
- Дефис и апостроф внутри слова — часть слова (`biało-czerwony`).
- Не трогаем: содержимое ссылок, `code`, `pre`, изображения, HTML-теги.
- Клик по слову даёт исходную форму без окружающей пунктуации.

### FR-7. Перевод

Порядок поиска (первый успешный выигрывает):

1. **Моя правка** (сохранена пользователем) — высший приоритет.
2. **Кэш** — перевод уже запрашивался.
3. **Внешний провайдер** — MyMemory (`api.mymemory.translated.net`), пара `pl|ru`.
4. Если провайдер не ответил или вернул мусор — сообщение с предложением ввести перевод вручную.

Детали:

- В кэш ключ — нормализованная форма (trim, нижний регистр), показываем перевод для исходной формы.
- Кэш хранится на сервере в `server/data/cache.json`, переживает перезапуск и очистку браузера.
- Запросы идут через наш сервер (не из браузера) — это решает CORS и прячет ключи, если появятся.
- Лимит MyMemory: 5000 знаков/день анонимно, 50 000/день при указании email в параметре `de`. В настройках сервера — поле для email.
- При исчерпании лимита (HTTP 429) — сообщение «Дневной лимит переводчика исчерпан» и предложение ввести перевод вручную; кэш продолжает работать.
- Перевод всегда одиночного слова, не фразы.

**Известное ограничение (важно):** польские слова в тексте стоят в косвенных формах, а машинный перевод одиночных словоформ ошибается. Проверка: `książka` → «книга» (хорошо), `książki` → «КНИГАЕГОИ» (мусор у MyMemory). Поэтому:
- перевод показывается вместе с пометкой «машинный перевод»;
- ручная правка — не костыль, а штатный механизм;
- в v2 — провайдер, который видит предложение целиком (LLM) и умеет лемматизировать.

### FR-8. Ручные правки

- В карточке «✎ Поправить» → инлайн-поле с текущим переводом → «Сохранить» / «Отмена».
- Правки хранятся отдельно от кэша (`server/data/overrides.json`), чтобы очистка кэша их не убивала.
- Правку можно удалить — тогда снова работает провайдер.
- Правка привязана к паре `язык|слово` в нижнем регистре.

### FR-9. Управление текстами

- Меню «⋯» на карточке: «Переименовать», «Удалить».
- Удаление — с подтверждением («Файл будет удалён с диска»), после — карточка исчезает из списка.
- Переименование меняет название в frontmatter и имя файла.

### FR-10. Настройки

- Размер шрифта читалки, скорость озвучки, (опционально) тема.
- Хранятся в `localStorage` браузера.
- Доступны из читалки и с главной.

### FR-11. Формат текста

Файл `texts/<имя>.md`, frontmatter необязателен:

```md
---
title: "Książka o kotach"
language: pl
level: A2
tags: [животные, рассказ]
created: 2026-10-23
---

# Książka o kotach

Ala ma kota. Kot nazywa się Mruczek.
```

- `title` — если нет, берётся первый заголовок `# ...`, иначе имя файла.
- `language` — если нет, `pl`.
- `level`, `tags` — необязательны, в MVP только отображаются (или игнорируются).
- Идентификатор текста = имя файла без расширения.

### FR-12. Личный словарь

- Кнопка «＋ В словарь» в карточке слова сохраняет слово, перевод, транскрипцию и ссылку на текст-источник.
- Повторное сохранение того же слова не создаёт дубликат, а обновляет запись.
- Если слово уже сохранено, кнопка показывает «✓ В словаре» и по нажатию убирает его.
- Словарь открывается панелью справа: с главной — кнопкой в шапке, из читалки — круглой кнопкой в правом нижнем углу (она закреплена и не двигается при прокрутке).
- В словаре: слово, IPA, перевод, источник, дата; кнопки «произнести» и «удалить».
- Слова из словаря подсвечиваются фоном во всех открытых текстах (CSS Custom Highlight API, без обёрток в DOM).
- Данные — `server/data/dictionary.json`, в git не попадают.

### FR-13. Страницы и прогресс

- Страницы считаются один раз по эталону «шрифт 18, экран 1920×1080» и не зависят от размера шрифта и окна. Переполнение прокручивается мышью.
- Текст режется по словам: абзац может начаться на одной странице и продолжиться на следующей (разрыв — по границе слова).
- Внизу закреплена панель: слайдер для быстрого перелистывания (с отметкой страницы-закладки), номер страницы (ввод вручную), общее число страниц, кнопки «назад/вперёд», процент прочитанного.
- Прочитанной считается страница, которую пользователь открыл; данные — `server/data/reading.json`.
- Раз в день сервер делает копию данных в `server/data/backups/<дата>/` (хранится 14 дней).

### FR-14. Закладки

- Кнопка «В закладки» ставит закладку на текущую страницу.
- При открытии текста с закладкой он открывается на ней.
- Закладку можно снять — тогда текст открывается на последней прочитанной странице.

## 7. Нефункциональные требования

- **Скорость:** перевод из кэша < 100 мс, из сети — < 2 с (p95). Список текстов — < 300 мс на 100 файлов.
- **Браузеры:** Chrome/Edge последних версий. Firefox — по возможности, Safari — не цель.
- **Адаптив:** от 360 px до широких мониторов.
- **Доступность:** контраст ≥ 4.5:1, видимый фокус, `Esc` закрывает карточку, озвучка и закрытие работают с клавиатуры.
- **Приватность:** наружу уходит только нажатое слово; тексты остаются на диске.
- **Надёжность данных:** тексты — файлы (бэкап = git или копия папки). Кэш и правки — JSON, потеря кэша безболезненна.
- **Простота запуска:** `npm install` → `npm run dev` → открыть `http://localhost:5173`. Без Docker и без отдельной базы данных.

## 9. Данные

```
texts/
  ksiazka-o-kotach.md          ← сами тексты (+ frontmatter)
server/data/
  cache.json                   ← кэш переводов
  overrides.json               ← мои правки переводов
```

`cache.json`:

```json
{
  "version": 1,
  "entries": {
    "pl|ru|książki": {
      "translation": "книги",
      "source": "mymemory",
      "fetchedAt": "2026-10-23T17:20:31Z"
    }
  }
}
```

`overrides.json`:

```json
{
  "version": 1,
  "entries": {
    "pl|ru|książki": { "translation": "книги (мн. ч., им. п.)", "updatedAt": "..." }
  }
}
```

## 10. Стек и обоснование

| Слой | Выбор | Зачем |
|---|---|---|
| Язык | **TypeScript** | Опечатка в поле — ошибка при сборке, а не белый экран в браузере |
| UI | **React 19** | Компоненты и состояние; самая большая база примеров, легко гуглить |
| Сборка | **Vite** | Dev-сервер с горячей перезагрузкой: сохранил файл — сразу видно |
| Стили | **обычный CSS** с переменными | Видно, что происходит; никаких утилитарных классов |
| Роутинг | **react-router** | Два маршрута: `/` и `/text/:id` |
| Markdown | **markdown-it** | Быстрый, расширяемый, без React-обвязки |
| Сервер | **Node + Express + TypeScript** | Маленький API: файлы на диске, кэш, прокси к переводчику |
| Хранилище | **файлы `.md` + JSON** | Прозрачно, бэкапится, не требует БД |
| Перевод | **MyMemory** за интерфейсом `Provider` | Бесплатно, без ключа, легко заменить |
| Озвучка | **Web Speech API** | Встроено в браузер, бесплатно, нормальное польское произношение |
| Тесты | **Vitest** | Быстрые юнит-тесты на токенизацию и frontmatter |
| Пакеты | **npm** workspaces (`client` + `server`) | Один `npm run dev` поднимает всё |

**Почему не:**

- **Next.js** — SSR и серверные компоненты для локального приложения избыточны.
- **Чистый статический SPA без сервера** — тексты жили бы в IndexedDB браузера, а не файлами; плюс CORS к переводчику. Проигрывает по главному принципу («тексты — файлы»).
- **Vue/Svelte** — нормальные варианты, но React полезнее для будущего и лучше покрыт примерами.
- **Tailwind** — разметка из двадцати классов читается новичком хуже, чем CSS с осмысленными именами.
- **База данных** — при десятках текстов это лишний слой; JSON хватает.

## 11. Архитектура

```
Браузер (React)
   │  fetch /api/*
   ▼
Vite dev-сервер ──прокси──▶ Express (Node, :3001)
                              ├── texts/*.md        (чтение/запись/удаление)
                              ├── data/cache.json   (кэш)
                              ├── data/overrides.json
                              └── api.mymemory.translated.net  (перевод)
```

- В dev: клиент на `:5173`, Vite проксирует `/api` на `:3001`.
- В prod: Express отдаёт собранный `client/dist` и API с одного порта.

## 12. API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | Проверка живости |
| GET | `/api/texts` | Список текстов (метаданные, без полного содержимого) |
| GET | `/api/texts/:id` | Текст целиком (markdown + метаданные) |
| POST | `/api/texts` | Создать: `multipart` (файл) или JSON `{title, language, content}` |
| PATCH | `/api/texts/:id` | Переименовать `{title}` |
| DELETE | `/api/texts/:id` | Удалить файл |
| GET | `/api/lookup?word=książki&lang=pl` | Перевод + источник |
| PUT | `/api/lookup/override` | Сохранить свою правку `{word, lang, translation}` |
| DELETE | `/api/lookup/override?word=…&lang=pl` | Удалить правку |

`GET /api/lookup` →

```json
{
  "word": "książki",
  "translation": "книги",
  "source": "mymemory",
  "cached": false
}
```

Ошибки — всегда JSON `{ "error": "human-readable русский текст", "code": "QUOTA_EXCEEDED" }`.

## 15. Риски и решения

| Риск | Решение |
|---|---|
| Машинный перевод словоформ врёт (проверено на `książki`) | Ручные правки + пометка источника; в v2 — провайдер с контекстом |
| Лимит MyMemory 5 000 знаков/день | Параметр `de` с email → 50 000; кэш; внятное сообщение при 429 |
| Нет польского голоса в системе | Проверка при старте, инструкция по установке голоса Windows |
| Node.js не установлен | Поставить LTS (winget) — нужен для запуска проекта |
| Неизвестные CORS-ограничения провайдера | Все запросы через наш сервер, браузер наружу не ходит |
| XSS через markdown | Рендер через markdown-it с `html: false`; HTML из текста не исполняется |
| Потеря текстов | Они файлы + git; `pnpm`-скрипт бэкапа не нужен |

## 16. Открытые вопросы

1. **Название.** «Project Sus» — рабочее или придумаем нормальное?
2. **Тёмная тема** — сразу в MVP или потом?
3. **IPA-транскрипция** (`książka [ˈkɕɔ̃ʂka]`) — нужна или хватает звука?
4. **Теги/уровень** (A1–C2) — будешь проставлять или это лишнее?
5. **Сколько текстов планируешь?** 10–50 (простая главная) или 200+ (нужны папки/теги)?
6. **Node.js** — ставим LTS на компьютер?
7. **Ключ DeepL/DeepSeek** есть? Тогда качество перевода можно поднять сильно и почти бесплатно.
