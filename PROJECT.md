# Project Sus — как всё устроено

**Версия:** 0.1.0 · личный проект · описание актуально на 26.10.2026

---

## 1. Что это

Читалка польских текстов с мгновенным переводом любого слова по клику.

- Тексты лежат обычными `.md`-файлами в папке `texts/`.
- Клик по слову → карточка: перевод на русский, транскрипция (IPA), озвучка, кнопка «в словарь», личная заметка.
- Текст разбит на страницы; внизу — слайдер, номер страницы, процент прочитанного, закладки.
- Есть личный словарь (с подсветкой слов в текстах) и избранные тексты.
- Тёмная и светлая темы, настраиваемый размер шрифта и скорость озвучки.

Приложение **однопользовательское и локальное**: сервер, тексты и данные живут на одной машине. Наружу уходят только нажатое слово (в MyMemory) и запросы транскрипции (Викисловарь).

## 2. Стек

| Слой | Технологии |
|---|---|
| Клиент | React 19.3, TypeScript 7, Vite 8, react-router-dom 7, markdown-it 15 |
| Сервер | Node.js (проверено на 24), Express 5.3, TypeScript, `tsx` (запуск без сборки) |
| Хранение | плоские JSON-файлы + `.md`-файлы |
| Перевод | MyMemory (HTTP API, без ключа) |
| Транскрипция | `pl.wiktionary.org` (MediaWiki API, разбор wikitext) |
| Озвучка | Web Speech API (системный голос) |
| Сборка | npm workspaces (`client`, `server`) |

Сторонних UI-библиотек нет — весь интерфейс и стили свои (`client/src/styles.css`, ~31 КБ, темы на CSS-переменных).

## 4. Запуск

```bash
npm install
npm run dev        # сервер :3001 + клиент :5173
```

- Клиент: <http://localhost:5173> (Vite проксирует `/api` на `:3001`).
- Сервер: <http://localhost:3001>.
- Продакшен: `npm run build` → `npm start` — сервер сам отдаёт собранный `client/dist` на `:3001`.

Скрипты: `dev`, `dev:server`, `dev:client`, `build`, `start`, `typecheck`.

Переменные окружения:

| Переменная | Зачем |
|---|---|
| `PORT` | порт сервера (по умолчанию 3001) |
| `MYMEMORY_EMAIL` | поднимает лимит MyMemory с 5 000 до 50 000 знаков в день |

## 5. Данные

### Тексты — `texts/`

```md
---
title: "Название"
language: pl
level: A2
tags: [тег]
created: 2026-10-23
favorite: true
---

# Заголовок

Текст.
```

- Всё, кроме текста, необязательно: без `title` берётся первый `#`, без `language` — `pl`.
- `favorite: true` — текст в избранном (показывается первым).
- Обложка — отдельный файл `texts/<id>.cover.jpg` (или `.png`, `.webp`), рядом с текстом.
- `id` — транслитерированный заголовок (`slugify`), при совпадении добавляется `-2`, `-3`.

### Служебные JSON — `server/data/`

| Файл | Ключ | Значение |
|---|---|---|
| `cache.json` | `pl|ru|słowo` | `{ translation, source, fetchedAt }` |
| `overrides.json` | `pl|ru|słowo` | `{ translation, updatedAt }` |
| `ipa.json` | `pl|słowo` | `{ value, checkedAt }` (негативный результат — 3 дня) |
| `dictionary.json` | `pl|słowo` | `{ id, word, lang, translation, ipa, textId, textTitle, createdAt, highlight }` |
| `notes.json` | `pl|słowo` | `{ text, updatedAt }` |
| `reading.json` | `<textId>` | `{ page, pages, readPages[], bookmarks[], updatedAt }` |
| `folders.json` | `<folderId>` | `{ id, name, textIds[], order }` (текст не больше чем в одной папке) |
| `backups/<дата>/` | — | копия всех JSON за день, хранится 14 дней |

Все JSON-файлы и `texts/` **исключены из git** (`.gitignore`).

## 6. API

Все ответы — JSON. Ошибки: `{ "error": "текст", "code": "КОД" }` с соответствующим HTTP-статусом.

### Тексты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/texts` | список: id, title, language, words, excerpt, cover, favorite |
| GET | `/api/texts/:id` | текст целиком (`body` — markdown) |
| POST | `/api/texts` | создать: `{ title, language, content }` |
| PATCH | `/api/texts/:id` | переименовать: `{ title }` |
| DELETE | `/api/texts/:id` | удалить текст и его прогресс |
| GET | `/api/texts/:id/cover` | обложка (image/\*) |
| POST | `/api/texts/:id/cover` | загрузить: `{ dataUrl }` (png/jpeg/webp, ≤3 МБ) |
| DELETE | `/api/texts/:id/cover` | убрать обложку |
| PUT | `/api/texts/:id/favorite` | избранное: `{ favorite: boolean }` |

### Папки

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/folders` | все папки по порядку |
| PUT | `/api/folders` | заменить список целиком: `{ folders: [{ id, name, textIds }] }`; сервер проверяет id, имена и то, что текст лежит не больше чем в одной папке |

### Перевод

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/lookup?word=&lang=` | перевод + `ipa` + `note` + `saved` |
| PUT | `/api/lookup/override` | своя правка: `{ word, lang, translation }` |
| DELETE | `/api/lookup/override` | сбросить правку |
| PUT | `/api/lookup/note` | заметка: `{ word, lang, text }` |

### Словарь

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/dictionary` | все слова + заметки + подсветка |
| POST | `/api/dictionary` | добавить: `{ word, lang, translation, ipa, textId, textTitle }` |
| PATCH | `/api/dictionary` | подсветка: `{ word, lang, highlight }` |
| DELETE | `/api/dictionary?word=&lang=` | удалить слово |

### Прогресс

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/reading/:id` | прогресс текста |
| PUT | `/api/reading/:id` | сохранить `{ page, pages, readPages, bookmarks }` |

## 7. Ключевые механики

### 7.1. Слово под курсором

Слова **не оборачиваются в `<span>`**: на «Ведьмаке» (112 600 слов) это дало бы десятки тысяч элементов и убило бы производительность.

- Координаты клика → `caretRangeFromPoint` → текстовый узел и смещение.
- Границы слова — `Intl.Segmenter` (учитывает польские диакритики и апострофы).
- Подсветка (наведение, активное слово, слова из словаря) — **CSS Custom Highlight API**: `::highlight(sus-saved | sus-hover | sus-active)`. DOM не меняется, смена темы на большом тексте ~30 мс.
- В браузерах без Highlight API клик и перевод работают, подсветки нет.

### 7.2. Перевод

Порядок источников (первый найденный побеждает):

1. **Своя правка** (`overrides.json`) — источник `override`.
2. **Кэш** (`cache.json`) — источник `cache`.
3. **MyMemory** — источник `mymemory`, результат кладётся в кэш.

- Ключ один для кэша и правок: `язык|целевой|слово` (слово в нижнем регистре).
- Правка перевода обновляет запись и в словаре, если слово там есть.
- Лимит MyMemory: 5 000 знаков/день, с `MYMEMORY_EMAIL` — 50 000. При исчерпании кэш и правки продолжают работать.
- Качество: MyMemory переводит одиночные слова и путается в словоформах (`książki` может выдать мусор). Поэтому ручная правка — штатный инструмент, а не костыль.

### 7.3. Транскрипция (IPA)

- Источник: `https://pl.wiktionary.org/w/api.php` (`action=parse`), из wikitext достаётся `{{IPA3|...}}`.
- Кэшируется в `ipa.json`; отрицательный результат не повторяется 3 дня.
- Ошибки сети глушатся: транскрипция — украшение, карточка из-за неё не падает.

### 7.4. Словарь и подсветка

- Слово сохраняется с переводом, IPA и ссылкой на текст-источник.
- Повторное сохранение обновляет запись, а не плодит дубликат (ключ `lang|word`).
- У каждого слова есть переключатель «В тексте» — выключить подсветку, оставив слово в словаре.
- Вместе со словом всегда отдаётся заметка (`note`): и в списке словаря, и в карточке после правки перевода.
- Дубликаты подсветки не создаются: `highlight` вычисляется на лету по списку сохранённых слов.

### 7.5. Заметки

- Заметка привязана к паре «слово + язык», хранится в `notes.json`.
- Доступна в двух местах: в карточке слова при чтении (раскрывающаяся «Заметка») и в карточке словаря.
- Сохраняется автоматически при уходе из поля; пустая — удаляет запись.
- **Заметка к слову, которого нет в словаре, автоматически добавляет слово в словарь.**
- Удаление слова из словаря удаляет и его заметку — так же, как удаление текста уносит его прогресс.
- Заметку отдаёт и `/api/lookup`, и правка перевода: иначе карточка теряла бы текст после «Исправить».

### 7.6. Страницы

Эталон вёрстки жёстко зафиксирован: **шрифт 18 px, колонка 912 px, межстрочный 1.75, 27 строк на страницу** — в единицах макета. Весь интерфейс свёрстан в масштабе **110%** (`UI_SCALE = 1.1` в `client/src/lib/markdown.ts`), поэтому в пикселях это 19,8 px и 1003,2 px: размеры в `styles.css` — значения макета, умноженные на 1,1, а шрифт из настроек умножается при выводе.

Алгоритм (`client/src/lib/markdown.ts`):

1. `markdown-it` парсит текст в блоки (абзацы, заголовки, цитаты, списки).
2. Блоки измеряются в скрытом контейнере с эталонными стилями (`getBoundingClientRect`).
3. Если абзац выше оставшегося места — разрез ставится **на конец предложения**: бинарным поиском по списку концов фраз (`sentenceEnds`) выбирается последняя фраза, которая влезает. Точки в сокращениях (`np.`, `itd.`, `m.in.`), инициалах (`J.`) и десятичных дробях (`3.5`) концом предложения не считаются.
4. Если в остаток страницы не влезает ни одна фраза: на непустой странице абзац целиком переносится на следующую (низ страницы остаётся пустым — это лучше разорванной фразы); на пустой странице (абзац или одна фраза длиннее страницы) — резервный разрез по слову.
5. Если измерения недоступны (высоты нулевые) — запасной режим по символам (75 символов в строке), без переноса по фразам.

Следствия:

- Страницы **не зависят** от размера шрифта и окна: при увеличении шрифта страница просто прокручивается.
- Смена шрифта не пересчитывает страницы (так задумано).
- Масштаб меняется одной константой `UI_SCALE`: колонка и шрифт растут вместе, их соотношение не меняется, поэтому страницы остаются те же.
- Страница может закончиться раньше (с пустым низом), но не посреди предложения.
- Из-за переноса по фразам общее число страниц может отличаться от прежних версий, но по-прежнему не зависит от шрифта и окна.
- Миграция настроек (`SETTINGS_VERSION = 2`) один раз сбрасывает сохранённый шрифт на 18, чтобы старые значения не ломали вёрстку.

### 7.7. Прогресс, закладки, панель

- Прогресс = `(номер страницы) / (всего страниц)` — зависит от открытой страницы, назад — уменьшается.
- До 10% показываются десятые («0,2%»), дальше целые проценты.
- Закладок может быть несколько; на слайдере у каждой свой флажок (клик по флажку → переход).
- При открытии текст встаёт на закладку **с наибольшим номером**.
- Панель внизу:
  - 1 страница — панели нет совсем (ни стрелок, ни процента);
  - 2 страницы — слайдер и поле номера, без кнопки закладки;
  - 3+ — всё, включая закладки.
- Листание: на экранах ≥1100 px — невидимые боковые зоны со стрелками ‹ › (подсвечиваются при наведении); уже 1100 px — боковые зоны скрыты, стрелки возвращаются в нижнюю панель.

### 7.8. Обложки

- Загрузка: только через меню «⋯» на карточке («Добавить обложку» / «Заменить обложку»); плейсхолдер без обложки — «?».
- Клиент уменьшает картинку до 480 px по длинной стороне, JPEG 85%, отправляет data URL.
- Сервер сохраняет файл `texts/<id>.cover.<ext>`; ссылка кэшируется по mtime (`?v=…`).
- На карточке обложка занимает всю высоту, при наведении «подлетает».
- Клик по обложке открывает просмотр: фон затемняется и размывается, закрытие — клик или `Esc`.
- Обложка переезжает при переименовании текста и удаляется вместе с ним.

### 7.9. Избранное

- Хранится в frontmatter текста (`favorite: true`), значит переживает переименование и видно в файле.
- В режимах «Сначала новые» и «А–Я» избранные идут первыми; в режиме «Свои» порядок ручной, звёзды на него не влияют.

### 7.10. Озвучка и настройки

- Web Speech API, системный голос для языка текста; если голоса нет — кнопка «Послушать» неактивна.
- Скорости: 0.5 / 0.75 / 1 / 1.25 / 1.5 (по умолчанию 0.75).
- Шрифт: 10–32 (по умолчанию 18) — в единицах макета; в пикселях ×1,1, потому что интерфейс в масштабе 110%.
- Тема: тёмная (по умолчанию) / светлая, хранится в `localStorage` (`project-sus:settings`, версия 2).
- Главная, панель «Вид»: плиток в ряд — авто или 2–5 (`tilesPerRow`), размер плиток — 70–150% шагом 10% (`tilesScale`). Геометрия карточки масштабируется целиком, текст — мягче (70–115%, `--tile-text`), чтобы на минимуме оставался читаемым.
- Если выбранное число плиток не влезает в окно, оно **автоматически уменьшается** и запоминается (ResizeObserver + `update({ tilesPerRow })`), поэтому в панели всегда показано то, что реально на экране. На окне ≤ 720 px всегда одна колонка.
- Высота карточек одинаковая: у карточки фиксированная высота (`240px × --tile-text`), заголовок режется по двум строкам, выдержка — по трём, а строка с метаданными прижата к низу.

### 7.11. Сортировка «Свои» и папки

- Три режима сортировки: «Сначала новые», «А–Я», «Свои» (`sort`). Выбранный режим хранится в настройках.
- «Свои» — ручной порядок: карточка перетаскивается на другую, и они **меняются местами**, остальные не сдвигаются. Порядок — массив id в настройках (`textsOrder`); новые тексты встают сверху, удалённые выпадают.
- Папки — отдельные сущности на сервере (`folders.json`), текст лежит не больше чем в одной папке. На главной они идут по три в ряд, а папка занимает треть ширины: обложки книжного формата 2:3 подстраиваются под её ширину (`container-type: inline-size`, размеры в `cqw`), веер раскрыт так, что у каждой карты видно название, а снизу — градиентное затемнение с названием текста. Курсор движется по горизонтали — ближайшая к курсору карта поднимается над остальными, ушёл курсор — всё возвращается; верхняя полоса колоды — «зона крестика», там переключения нет, чтобы кнопка удаления не убегала, а ниже (и при диагональном движении вниз) карты меняются. Клик по карте открывает текст, «×» убирает текст из папки.
- Обложки в сетке тоже книжные: ширина считается как 2:3 от высоты карточки, поэтому форма не зависит от размера плиток.
- Положить текст в папку можно и мышью: карточку из сетки перетаскивают на колоду — она подсвечивается пунктиром и принимает карточку.
- Тексты из папок не дублируются в сетке (при поиске показываются все найденные, папки на время поиска скрываются).
- Папку можно создать кнопкой «+ Папка», переименовать и удалить из меню «⋯» на самой папке; положить текст в папку — через меню карточки «В папку…». Удаление папки не удаляет тексты, они возвращаются в сетку.

## 8. Клиент: маршруты и состояние

| Маршрут | Экран |
|---|---|
| `/` | главная: поиск, сортировка, папки-веера, карточки текстов, меню «⋯», звёзды, обложки |
| `/text/:id` | читалка: страница текста, карточка слова, словарь, панель страниц |

Состояние:

- настройки — `SettingsProvider` (localStorage): тема, шрифт, скорость, вид плиток, режим сортировки, ручной порядок (`textsOrder`);
- список текстов, папки и словарь — загрузка через `api` при открытии; папки сохраняются целиком одним PUT;
- прогресс чтения — на сервере, сохраняется с задержкой ~500 мс;
- карточка слова — локальное состояние компонента, позиция считается по координатам слова.

## 9. Сервер: как устроен

- `JsonStore` держит данные в памяти, при изменении пишет файл атомарно (`.tmp` → `rename`).
- Роуты разбиты по доменам: `texts`, `lookup`, `dictionary`, `reading`.
- Статика: если существует `client/dist`, сервер отдаёт её и `index.html` на все GET.
- Бэкап: при старте раз в день копирует все JSON из `server/data` в `backups/<дата>/`, хранит 14 дней.
- Ошибки — класс `ApiError` → JSON `{ error, code }`; всё остальное — 500 `INTERNAL`.

## 11. Ограничения и особенности

1. **Перевод без контекста.** MyMemory видит одно слово, а не предложение, поэтому формы и многозначность страдают. Частично лечится ручной правкой.
2. **Лимит переводчика.** 5 000 знаков/день без email, 50 000 с `MYMEMORY_EMAIL`.
3. **Страницы фиксированы под макет 18 px / колонку 912 px** (при масштабе 110% — 19,8 px / 1003 px). Крупный шрифт или узкое окно не пересчитывают страницы — появляется прокрутка. Это осознанное требование, а не баг.
4. **Нет авторизации.** Приложение рассчитано на одного пользователя; сервер слушает порт на всех интерфейсах, поэтому в локальной сети он виден. Наружу не публиковать без пароля/фаервола.
5. **Бэкап покрывает только JSON.** Тексты и обложки в `backups/` не попадают — их надо копировать отдельно.
6. **Обложки хранятся в 480 px** — в крупном просмотре картинка слегка мягкая.
7. **Тема не переключается автоматически** по системе — только вручную.
8. **Слово выбирается только кликом** — клавиатурной навигации по словам нет.
9. **Пальцы/тач**: основные жесты — клик; интерфейс задуман под мышь и экран 1080p.

## 12. История решений (почему так)

- **Убрали выбор переводчика и Google.** Неофициальный эндпоинт Google из этой сети недоступен (редирект), поддержка двух провайдеров без пользы усложняла код. Остался MyMemory.
- **Убрали `<span>`-разметку слов.** 112 600 слов — десятки тысяч элементов, смена темы занимала секунды. Перешли на Highlight API.
- **Пагинация по измерению высот, а не по символам.** Модель «84 символа в строке» не совпадала с реальностью (~75), страницы рвались посреди строки. Теперь высота блоков измеряется в браузере, а разрез ищется бинарным поиском по реальному тексту.
- **Процент прочитанного — от текущей страницы.** Сначала считался по списку посещённых страниц, но оказалось, что пользователь ждёт «сколько прочитано от начала»: вернулся назад — процент меньше.
- **Закладок несколько, открытие — на старшей.** Так текст всегда возвращает к самому дальнему месту, а не к случайной метке.
- **Заметки перенесли в словарь.** Первая версия была только в карточке слова при чтении; в словаре заметок не хватало. Теперь они в обоих местах, а заметка автоматически добавляет слово в словарь.
- **Короткие тексты без лишней панели.** Одна страница — панель не нужна вообще; две — не нужны закладки.
